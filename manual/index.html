1. Introduction & Overview#

RXB Workstation is a pad-first production environment for beat creation, live triggering, scene sequencing, and performance arrangement.

Pads are always live — you never need to arm a track to play.

The MAIN view provides quick pad playback control, and is accessible through the MAIN tab. The GRID, DAW, XPAD, SAMPLE, SONG, KEYGRP, FXRACK, MIXER, MACRO, INPUT, MIDI, DMX, and SYSTEM views expose deeper workflow controls.

  • The full tab bar order is: MAIN, MIXER, GRID, DAW, FXRACK, INPUT, XPAD, KEYGRP, SAMPLE, SONG, MACRO, MIDI, SYSTEM, DMX.
  • The DAW view is a Windows-first multi-lane backing-track workspace with a master lane plus seven aux lanes, linked transport, and per-lane mix controls (see Section 15).
  • The DMX view is a DMX512 / Art-Net lighting controller for driving fixtures in sync with the transport (see Section 28).
  • Each project stores scenes, pad settings, layer names, sample references, backing-track metadata, and routing preferences.
  • The desktop runtime uses a C++ native transport backend with a JS fallback path retained for safety.
  • Layout presets currently available in LAYOUT MODE are Default, Pads Left, and Studio / Mix.

4. Core Concepts#

Scenes, Banks, and Source Pairing#

  • Scenes are split into two linked ranges:
  • Main scenes: 1-8 (S1-S8, red context)
  • Keygroup-linked scenes: 9-16 (K1-K8, teal/green context)
  • Banks are performance/sample banks A / B / C / D.
  • Source toggles in song steps use MAIN and KEYGRP ON/OFF states.

If both scene systems are used in one arrangement, RXB adjusts playback routing to match step-level source settings.

5. Pad Grid Operation#

The GRID view provides step sequencing, velocity editing, and per-step performance controls.

  • Toggle steps directly on the grid.
  • Use edit modes such as velocity/probability/ratchet for groove shaping.
  • Use PLAY, MUTE, SOLO, and BATCH mode buttons to control pad behavior.

A populated step grid is shown in Figure 5.1.

The BAR button (next to the Play button in the GRID) toggles the grid view between Bar 1 (steps 1–16) and Bar 2 (steps 17–32), allowing you to view and edit both halves of a 32-step pattern. The current bar number is displayed on the button.

BATCH mode — tap pads to build a multi-pad selection (pads highlight in blue). The knobs panel switches to the BATCH EDIT surface showing 10 parameter knobs (VOL, TUNE, REV, DEL, CUTOFF, DRIVE, PAN, ATK, DEC, REL). Moving any knob sets that parameter to the same value across all selected pads simultaneously. Press BATCH again or CLEAR inside the panel to exit.

Choke Groups#

Two pads in the same choke group cannot sound at the same time. Whichever one you hit last silences the other.

This models a single physical instrument. The clearest example is a hi-hat: one pair of cymbals on one stand, so a closed hat and an open hat are the same object in two states. Striking the closed hat has to stop the open hat ringing, because physically the pedal has just clamped the cymbals together. Drum machines and samplers have called this a choke group, or a mute group, for decades.

Setting a choke group. Select a pad, open the MAIN tab of the PAD CONTROL SURFACE, and use the CHOKE dropdown in the panel header, next to AT:. Choose OFF (the default — the pad plays independently) or a group from 1 to 16. The control highlights when a group is set, so you can see at a glance which pads are wired together. There are 16 groups and 16 pads per bank, so a kit can never run out.

The setting belongs to the pad, not to the scene, and it is saved with the project.

Choke groups in the factory banks. Two banks ship with a group already assigned, both on the hats:

BANKPADSGROUP
ACH, OH1
BHAT CL, HAT OP, HAT PD1

Banks C and D ship with no choke groups. If you load your own sample onto one of the pads listed above, it inherits that pad's choke group — set CHOKE to OFF if you want the pad to play independently.

Useful beyond hi-hats. A choke group is just a rule that a set of pads is monophonic together, so it is worth reaching for whenever overlapping tails are the problem rather than the point:

  • Two or three 808s in the same group, so a new bass note stops the previous one instead of stacking into mud.
  • A row of vocal chops in one group, so only one vocal is ever heard.
  • Risers and downlifters, so a new transition cancels the one still running.

PRO TIP

A pad in a choke group also chokes itself — retriggering it stops its own
previous note rather than layering a second copy. That is what makes a group of
one a usable "make this pad monophonic" switch.

6. Keygroup Mode (KEYGRP)#

When KEYGRP is active, pads become note keys derived from root note, scale type, and octave settings.

  • In normal mode, each pad triggers its own sample identity.
  • In KEYGRP, pad hits transpose the currently targeted sample voice.
  • KEYGRP Pair and MAIN Pair control linked-bank audibility from the XPAD/sequencer link surface.

The MIXER view stacks five cards top to bottom: MASTER, DELIVERY METERING, MIX BUSES, SIDECHAIN, and the channel strip area. When the panel is shorter than its content, the whole view scrolls vertically — no controls are ever hidden; when the panel is taller, the channel strips grow to fill the extra height.

Mix Buses — Group Faders for Drums, Music, Vox, FX, and Backing#

Location: MIXER view → MIX BUSES card (between DELIVERY METERING and SIDECHAIN)

Everything you hear is grouped onto one of five buses on its way to the master chain. A bus is a group fader: it lets you move the balance between whole categories of sound — pull all the drums down together, push the vocal up — without touching the individual pad faders underneath.

BUSWHAT FEEDS IT
DRUMSEvery pad you have not sent somewhere else (see Sending a Pad to a Bus below)
MUSICThe keygroup bus, plus any pad you assign here
VOXLive input monitoring
FXReverb, delay, and FX-rack returns
BACKINGThe backing track and the DAW aux lanes

Each strip carries the same five controls:

CONTROLFUNCTION
Level sliderBus fader, with the current value shown in dB beside the bus name. Unity (0.0 dB) is the default
MeterPost-fader output level for that bus — it follows the fader, pan, and mute, so it shows what the bus is actually sending to the master. Amber above −1.4 dBFS, red on clip
PANPlaces the whole group in the stereo field. C is centre; values read as L50 / R50
MMutes the bus
SSolos the bus. Any solo silences the un-soloed buses; if a bus is both muted and soloed, mute wins
MST / DIRRouting. MST (default) sends the bus through the master 3-band EQ. DIR routes it around that EQ

DIR exists mainly for the BACKING bus: a finished backing track has usually been mastered already, and pushing it through your master EQ colours it a second time. DIR keeps it out of that EQ — but it never bypasses the master compressor or the safety limiter, so it can still never clip the output.

Bus settings are saved with your project. A project saved before this feature existed simply opens with every bus at unity, centred, unmuted, and set to MST — which is exactly how it sounded before, so nothing you have already made will play back differently.

See Figure 7.2 for the five bus strips with SOLO active.

PRO TIP

When a mix feels crowded, solo the DRUMS bus and then the MUSIC bus in turn — because these are group faders, you are auditioning the whole layer as it sits in the mix, which makes it far easier to hear which group is masking the other than soloing pads one at a time.

Sending a Pad to a Bus#

Location: MIXER view → pad channel strip → BUS selector (under the VOL readout)

By default every pad goes to the DRUMS bus. That is fine for a kit, but it is not what you want once a pad is carrying a bassline, a vocal chop, or a texture — those want their own group fader. The BUS selector on each pad strip sends that pad wherever you like:

SETTINGWHERE THE PAD GOES
AUTOThe default. Normal playback goes to DRUMS; KEYGRP playback goes through the keygroup bus into MUSIC
DRMThe DRUMS bus
MUSThe MUSIC bus — useful for melodic pads you want grouped with your keygroup parts
VOXThe VOX bus — for vocal chops and one-shots, so they ride with your live input
FXThe FX bus
BCKThe BACKING bus

An assigned pad shows its bus highlighted, so you can read the whole routing of a kit down the rail at a glance.

The change takes effect immediately, even on a pad that is still ringing — you can reassign while the sequencer is running and hear it move. Assignments are saved with your project, are the same in every scene, and a project made before this feature existed opens with every pad on AUTO, which is exactly how it sounded before.

IMPORTANT

While KEYGRP mode is on, the selected pad's strip shows a locked KEY chip instead of the selector. All keygroup pads share one keygroup bus — that is what gives them their own EQ and compression before they reach MUSIC — so keygroup playback always uses that chain, whatever the pad is assigned to. Leave KEYGRP mode and the selector comes back, unchanged.

Figure 7.3 illustrates pads assigned to different buses.

PRO TIP

Put your kick and snare on AUTO, move sub/bass pads to MUS, and send vocal chops to VOX. Now the DRUMS fader really is a drum fader: you can duck the whole kit under a vocal without dragging the bass down with it.

8. File Management#

Project Contract and Folder Conventions#

Use these exact names for stable project portability.

  • Primary file: project.rxbproj
  • Legacy mirror: project.json
  • Backups: project_backup_TIMESTAMP.rxbbak
  • Sample folder: Samples/
  • Export folders: Bounces/, MIDI/

Folder-open discovery order:

  1. project.rxbproj
  2. project.json
  3. First matching .rxbproj or .json in project root

Save and Open Actions#

  • SAVE PROJECT writes both project.rxbproj and project.json, then creates a timestamped backup.
  • COLLECT + SAVE copies required sample assets to Samples/ and writes project files.
  • SAVE AS creates a new project destination while preserving project metadata links.
  • OPEN supports folder-first and direct-file project open flows.
  • NEW CLEAN FILE initializes a fresh project state.

Backups are auto-cleaned to retain the newest three backup files per project root.

WARNING

Do not move or rename project sample assets outside RXB after saving. If links break, run COLLECT + SAVE to rebuild a portable project state.

9. Troubleshooting#

Use this section for common recovery and stability checks.

Missing Samples or Broken Links#

  • If a file shows as missing, relink from the relevant load action first.
  • Re-run COLLECT + SAVE to rebuild portable sample references in Samples/.
  • Reopen the project and confirm all pad layers (L1-L4) resolve.

Backing Track Import Failures#

  • Confirm extension is one of: WAV, AIFF, MP3, M4A, FLAC, OGG, WMA.
  • Confirm file size is below 256 MB and duration is below 45 minutes.
  • Use desktop runtime for best WMA compatibility.

Keygroup Mix Clarity#

  1. Confirm target track state is not muted/solo-filtered unexpectedly.
  2. Raise MID and HIGH slightly in KEYGRP ENGINE.
  3. Add moderate COMP, then trim GAIN to avoid clipping.
  4. Increase POLYPHONY if notes are cut early.

IMPORTANT

After changing the song structure, stop and restart transport once to ensure fresh plan application.

Native Transport Fallback#

The desktop runtime drives playback timing from the C++ native transport backend. If the native transport drops mid-session, playback continues seamlessly on the JS clock and the status line shows:

Native transport dropped - playback continued on the JS clock. Stop/play to retry native.

No action is required — timing continues uninterrupted. Stop and restart the transport once to retry the native backend.

Audio Device Not Released After Close (Windows)#

On Windows, if the microphone or system audio recording indicator (taskbar) stays active after RXB is closed, the audio capture device was not fully released.

Close the app and check Task Manager for any lingering RXB or Electron processes. Terminate them to release the device.

If the device indicator persists even after full process exit, confirm your audio driver and virtual device software (e.g. VB-Audio Cable, Stereo Mix) are up to date.

Addendum — September 3, 2026#

Four audio-engine changes, all in Steam BuildID 25096633.

Choke groups are now a control, and they are documented. Choke groups had existed since the first release but there was no way to see or change one, and the only mention in this manual was a single clause in the Bank B kit description. Bank A's CH/OH pair was not documented at all. There is now a CHOKE selector on the MAIN tab offering OFF and groups 1–16, and a full explanation in Section 5.

Choke groups now cut at the right moment. The sequencer queues hits up to 100 ms before they are heard, and a choke was being applied when the hit was queued rather than when it sounded. Two consequences, both fixed:

  • A ringing pad lost 75–100 ms of its tail, so an open hat followed by a closed hat left a hole in the groove instead of one hat cutting the other.
  • Worse, two pads of the same group on the same step — a closed and an open hat together — could silence one of them entirely, producing no sound at all rather than a short one.

Song-mode tempo changes land on the beat. A per-step BPM override reached the transport clock a step late, so a section boundary played one step at the previous tempo. Dropping from 120 to 30 that is a step four times too fast, right where the change should be heard. Tempo now changes on the section boundary.

The output ceiling holds. The always-on safety limiter was not limiting. Measured on the shipped signal path, four pads at factory levels drove the output to +7.8 dBFS — past full scale, into clipping. The limiter now holds below -1 dBFS across the full range.

PRO TIP

The limiter fix is the one change here you may hear on existing projects. Loud,
dense passages that previously ran hot into clipping are now held back instead,
so they will sound quieter and more controlled. Nothing is lost — that material
was distorting before. If a mix now feels quiet, raise the pad or bus levels
that were relying on the clipping for loudness.

Undo / Redo#

Undo/Redo uses a bounded dual-stack snapshot model for edit history.

  • Undo: Ctrl+Z / Cmd+Z
  • Redo: Ctrl+Y or Ctrl+Shift+Z / Cmd+Shift+Z
  • History depth: up to 40 states

What undo covers. The history holds your sequencer scenes and pad state — step edits, pad parameters, sample edits, chops, MIDI import and captured input. It also covers clearing the backing track and clearing a DAW lane: both are undoable, and Ctrl+Z puts the audio back. It does not cover song structure, mixer, mix buses, FX, or DMX; those are project state outside the edit history.

Edits are grouped into gestures. A continuous run of step edits counts as one undo step, so Ctrl+Z after tapping in a hi-hat pattern removes the pattern rather than the last cell. Pause for about a second and the next edit starts a fresh undo step; a long unbroken run also breaks into separate steps every few seconds, so no single Ctrl+Z can swallow minutes of work. Velocity and pan scrubs group the same way, per step.

What happens at the boundary. If your last action was outside that scope — for example a song-structure or mixer change — Ctrl+Z does not reach past it into your sequencer work. Instead the header shows:

Nothing to undo — <action> is outside undo history; your last sequencer edit was left alone.

Press Ctrl+Z again and it resumes normally, undoing your most recent sequencer edit.

IMPORTANT

Undo restores a cleared backing track or DAW lane from memory, not from disk. It
is a safety net for a mis-click during a session — it is not a substitute for
saving, and it does not survive closing the project.

13. Transport and Tempo Controls#

BPM#

The BPM field is shown in the transport strip. Click the value and type a new tempo, or use the up/down arrows. The accepted range is 20–300 BPM.

Swing#

The Swing control adds rhythmic offset to alternating steps. The displayed range is 50–75:

  • 50 — straight timing (no swing)
  • >50 — the 1st, 3rd, 5th … (even-indexed) step of each pair is stretched longer and the 2nd, 4th, 6th … step is shortened, producing a swing feel
  • 75 — near-maximum swing offset (approaching triplet feel, which lives near ~66.7)

Swing is applied per-step at render time and affects pad playback and the step sequencer. Backing tracks align to the sequencer grid, so swing indirectly shifts their perceived beat positions without altering the backing-track audio itself.

Metronome#

The METRONOME toggle lives in the SYSTEM tab. When active, a click fires on every beat (every 4 steps), with an accented click (1 kHz vs 800 Hz) on the bar downbeat. The click is routed directly to the audio output, bypassing the master bus and FX chain so master EQ, compression, and effects do not colour it.

CONTROLFUNCTION

Backing Track Mute (MUTE / LVL)#

A MUTE button sits next to the LVL slider in the backing-track strip (disabled when no track is loaded; lit red while muted).

  • Mute is gain-only with a short click-free ramp — the track keeps playing silently, so the playhead, grid lock, and song-section mapping all stay exactly where they are.
  • Your LVL setting is untouched: the slider dims and the percentage readout is struck through while muted, and unmuting restores the same level.
  • The sample-editor preview stays audible while the backing track is muted — MUTE silences only the backing track itself.

Waveform Seek — Song Follows (Sequencer is Master)#

Clicking or scrubbing the backing-track waveform seeks the track. When GRID LOCK is on, the seek moves both: the Song Mode pointer (current section and bar) snaps to the song section under the new playhead position, and during Song Mode playback the matching scene is applied immediately. Seeks resolve to the nearest bar, the finest boundary a section can start or end on.

  • The cued song position survives STOP — pressing PLAY resumes from the cued section rather than restarting from the top.
  • Editing a section's BARS count or per-step BPM re-pins the playhead to the same musical position inside the same section, so the coloured section bands, the playhead, and every seek always agree.
  • With GRID LOCK off, the backing track is independent and a waveform click behaves as a plain seek.

20. Auto-Sampler#

The Auto-Sampler automates the process of building a multi-sample keygroup from an external synthesizer or instrument. It sends MIDI notes out through your MIDI sync output, records each note as a sample, assigns each capture to a successive pad, and creates a full keygroup multi-sample map automatically.

Requirements#

  • A MIDI sync output must be selected in MIDI → SYNC STACK → MIDI OUTPUT.
  • The selected MIDI output must be connected to the instrument you want to sample.
  • Input monitoring must be active (or will be started automatically).
  • Sufficient empty pads must be available starting from the selected pad.

Workflow#

  1. Connect your synthesizer/instrument MIDI input to a MIDI interface.
  2. In MIDI → SYNC STACK, select the MIDI output connected to the instrument.
  3. In the XPAD or SAMPLE tab, open the Record Input to Pad card.
  4. Select the start pad and layer where captures should begin.
  5. Click SHOW SETTINGS to configure the note range and timing.
  6. Click START AUTO-SAMPLE.
  7. RXB will automatically: send Note On → wait (Hold) → send Note Off → wait (Tail) → capture → move to next pad.
  8. When complete, the anchor pad is set to Keygroup mode with a full multi-sample zone map.

Odd-Length Sections, Turnarounds and Pickups#

A sequencer pattern is 32 steps — 8 beats, or two bars of 4/4. Sections built from whole pattern loops can therefore only ever be an even number of bars. Setting BARS to an odd number ends the section halfway through a loop, which is what lets you write a 7-bar verse or a single-bar lead-in.

When a section runs an odd number of bars, the ½ BAR toggle decides what that final bar plays:

SETTINGWHAT YOU HEAR
1STThe trailing bar repeats the bar the section opened on — the section is simply cut short
LASTThe trailing bar plays the pattern's second bar instead — its fill or turnaround

Building a turnaround: set a section to an odd length (say 7 bars) and switch ½ BAR to LAST. Bars 1–6 play the pattern normally and the seventh plays the pattern's second bar, so the section ends on its fill rather than restarting.

Building a pickup: add a section of 1 bar with ½ BAR set to LAST, and place it immediately before the section it leads into. The single bar plays that pattern's second bar as a lead-in.

Even-length sections behave exactly as before — the toggle is greyed out because it has nothing to decide.

IMPORTANT

A project containing an odd-length section, opened in a build older than 2026-08-08, will play that section one bar short. Older builds round the stored length down to a whole loop.

Per-Pad Scene Profiles#

Each pad carries 16 independent sound profiles — one per scene slot. Scenes 1–8 and 9–16 each form a bank with an anchor scene (scene 1 and scene 9 respectively).

Each profile stores the complete sound state for that pad in that scene:

SECTIONPARAMETERS
MAINPitch, resonance, filter cutoff, drive, aftertouch depth, aftertouch target
ENVAttack, decay, sustain, release
COMPCompressor amount, ratio, attack
FXReverb, delay, pan, filter type
FXRACKPer-module send levels (GRN, VRB, ECH, AIR, PSY)

Step performance parameters (probability, ratchet, humanize) are not part of scene profiles — they remain global per-pad.

Anchor Scenes and Sync#

  • Anchor scenes (scene 1 and scene 9) always read directly from their own stored profile (or fall back to pad-level defaults if no profile exists).
  • Non-anchor scenes (2–8 and 10–16) default to synced — a synced scene follows the anchor's current values in real time rather than storing its own.
  • Syncing is a live link: if you change a parameter on the anchor scene, all synced scenes immediately reflect that change.

Creating and Removing Scene-Specific Sounds#

  • To give a scene its own independent sound: click the SYNC TO SCENE 1 / SYNC TO SCENE 9 button on a synced scene. RXB captures the anchor's current values as a starting point and stores them as an independent profile for that scene.
  • To re-sync a scene back to the anchor: click the button again — the profile slot resets to null and the scene follows the anchor live.
  • Editing any MAIN/ENV/FX/COMP/FXRACK parameter on an anchor scene stores the changes in that anchor's profile slot. Non-anchor synced scenes immediately reflect the change.

Playback Behavior#

  • Live pad hits, sequencer playback, and the arpeggiator all resolve scene profiles consistently — the same sound is used whether a pad is triggered manually or by a sequencer step.
  • Switching the active scene during playback immediately pushes resolved compressor parameters to the audio engine for all pads — no retrigger required.

IMPORTANT

Editing parameters on a synced (non-anchor) scene does nothing — the controls are locked. Switch the sync off first to create an independent profile, then edit.

PRO TIP

Use scene profiles to build variation across your 8 main scenes — same pads, different tones. Scene 1 becomes your reference sound; tweak filter, drive, or reverb on scenes 2–8 for texture shifts between pattern sections.

Scene Copy/Paste with Sound State#

Scene copy/paste (GRID → scene context menu) captures and transfers the full per-scene sound state alongside the pattern data.

When you paste a scene, the destination scene receives both:

  • The step pattern from the source scene
  • The per-pad scene-profile sound settings from the source scene (tune, filter, envelope, compressor, FX sends)

This ensures pasted scenes sound identical to their source rather than playing with the destination scene's existing pad sounds.

Visual Performance Enhancements#

XY Layer Flash on Step Trigger#

During sequencer playback, the corner layer tags on each XPAD pad button briefly brighten when a step fires for that pad. Layers with a bilinear XY weight of 0.01 or higher will flash.

This gives immediate visual feedback about which layer(s) are contributing to each triggered step based on the current XY position:

  • Top-left (L1) flashes when the XY position is in the top-left quadrant.
  • Top-right (L2) flashes when in the top-right quadrant.
  • Bottom-left (L3) and bottom-right (L4) similarly.
  • When XY is centered, all four layers flash proportionally.

The effect uses the existing corner tag display — no separate overlay is added.

Waveform Cursor Step Tracking#

When the SAMPLE view is open and the currently selected pad fires a step during sequencer playback, the waveform cursor animates forward in real time, tracking the playback position through the sample.

No new audio node is created for the visual update — a RAF-based clock drives the cursor independently of the audio engine, synchronized via the step trigger.

28. DMX Lighting (Art-Net Output)#

The DMX tab (rightmost in the tab bar) turns RXB into a lighting controller. It transmits a full DMX512 universe over Art-Net (UDP), so you can drive fixtures, dimmers, and LED rigs in sync with your performance. Art-Net output uses the desktop runtime's network layer — it is a Windows/desktop feature and is not available in browser-only contexts.

The full DMX surface is shown in Figure 28.1.

The ART-NET OUTPUT card configures the network destination:

Beat Sync Modes#

Beat sync runs only while the transport is playing, output is ENABLED, and BPM is above zero. The beat interval follows the project tempo (60 ÷ BPM seconds).

  • Flash on beat — momentarily forces the master dimmer to full (255) for a short pulse on each beat, then returns to the set level. Use for strobe/accent effects locked to tempo.
  • Scene advance on beat — steps through the Scene Bank (SCN 1 → 8, wrapping) one scene per beat, recalling each scene's channel snapshot in turn. Use for automated, tempo-synced lighting changes.

The SCENE BANK stores up to eight lighting snapshots (SCN 1–SCN 8). Each slot has three actions:

PRO TIP

Build a few looks with the channel grid, STOR each into SCN 1–8, then enable BEAT SYNC → Scene advance on beat to run a hands-free, tempo-locked light show.

Channel Grid (DMX 1–512)#

The CHANNELS — DMX 1–512 card shows the full universe as a 16-column grid of cells. Each cell displays its channel number and current value (0–255); brightness and red tint track the value.

  • Click a cell to open the inline channel editor — a 0–255 slider plus a numeric field for exact entry. Click the cell again or the × to close the editor.
  • BLACKOUT instantly zeroes all 512 channels (live output, not the stored scenes).

The footer summarises the universe: {n}/512 active · master ×{ratio} · click cell to edit.
